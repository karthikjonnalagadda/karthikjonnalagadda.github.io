Medical Multimodal AI Assistant

Problem. A clinician's evidence is split across formats — lab PDFs, chest X-rays, and free-text symptoms — while a general LLM answers from memory rather than from the patient's actual results. This system reads all three, retrieves matching clinical literature, and returns a structured assessment with the evidence attached.

Request path — POST /analyze

Engineering decisions

  • Provider-agnostic LLM layer. Groq, OpenAI, xAI and local BioGPT sit behind one interface, so switching models is a config change rather than a code change.
  • Vision as a registry, not a hard dependency. TorchXRayVision is preferred, a CheXNet checkpoint loader is next, HuggingFace classifiers last — each degrading rather than crashing.
  • Hybrid retrieval. Dense 384-dim embeddings alone missed exact lab terms, so lexical scoring runs alongside them.
  • Lazy model initialisation keeps multi-hundred-megabyte weight loads off the request path.

Challenges solved

  • Schema-contract defect. Prompts asked for "JSON-compatible markdown" while the wrapper enforced response_format=json_object. Parsing failed intermittently. Fixed by enforcing a strict six-field clinical schema plus a coercion layer, locked behind regression tests.
  • Duplicate embeddings on re-ingest. Chunk IDs were non-deterministic, so re-running ingestion silently doubled the vector store. Now content-hash based, making ingestion idempotent.
  • Grad-CAM hooks and X-ray normalisation were producing wrong attribution maps — both fixed and committed.
# deterministic chunk IDs → idempotent re-ingestion
chunk_id = sha256(f"{source}:{ordinal}:{text}")
collection.upsert(ids=[chunk_id], ...)

Testing & verification

  • 50 tests, 100% passing across OCR, vision, RAG, chunking and API layers.
  • 60% statement coverage over 3,477 statements; hybrid retriever at 89%.
  • pre-commit, flake8 and pylint gates on every commit.
  • Runtime dependencies split from development set to cut install surface.

Known gaps

  • Per-class ROC-AUC on a held-out NIH split is not yet recorded — the training harness exists but the run isn't published.
  • Two modules sit at 0% coverage and are candidates for deletion.

SafeInbox — Real-Time Spam Detection

Problem. A spam classifier is only useful against live mail, not a static CSV. SafeInbox pulls real inbox messages over the Gmail API and IMAP, classifies them with a scikit-learn model, and serves results through a MERN dashboard — with the model running inside a Node runtime rather than a separate service to operate.

Inference path — live mail to verdict

Engineering decisions

  • No separate model server. Express invokes a Python process directly — one deployable instead of two, appropriate at this scale.
  • Artifacts, not retraining. Vectoriser and model are persisted and loaded once, so inference never pays training cost.
  • Near-balanced corpus (13,263 ham / 13,709 spam) means accuracy is a meaningful headline number rather than a misleading one.
  • 1–3 gram TF-IDF with English stop-word removal, yielding 1,034,706 features.

Security

  • JWT authentication with bcrypt password hashing.
  • Protected routes enforced on both API and React client.
  • Gmail scope limited to gmail.readonly — the app can never send or delete.

Delivery

  • Dockerfile and Jenkins pipeline committed for reproducible builds.

Known gaps

  • No held-out test split is committed, so precision, recall and F1 are not published. The trained artifacts are in the repo, so this is a short exercise rather than a rebuild.
  • Only one classifier ships; a Naive Bayes / logistic regression / SVM comparison would justify the model choice on evidence.

Genomic Dimensionality Reduction & Clustering

Problem. Genomic expression matrices have far more genes than samples, so clustering them directly is unstable. The question was which projection preserves biological structure — answered by measuring both rather than assuming.

0.66ARI — SVD
0.56ARI — NMF
  • Python
  • Scikit-learn
  • Pandas
  • NumPy
  • Matplotlib
  • Seaborn

Method

  • SVD and NMF benchmarked ahead of K-Means; SVD selected on measured cluster agreement (ARI 0.66 vs 0.56).
  • A Random Forest trained on the reduced space validated separability independently of the clustering objective — guarding against clusters that are artifacts of the projection.
  • EDA on gene variability, correlation heatmaps and top-gene plots to interpret clusters biologically.

Known gaps

  • Silhouette score, explained-variance ratio and dataset dimensions are not published alongside ARI.
